# Mode Auto (paris live rapides) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un mode « Auto » armé par l'utilisateur qui choisit un événement live Betclic, fait analyser des marchés rapides par JEV et place lui-même les paris dans des limites codées en dur.

**Architecture:** Modules purs testables sous `extension/src/auto/` (guard, clock, scanner, selector, readers, tracker, controller) ; `executor.js` est le seul module qui clique/saisit/valide. Machine à états persistée dans `chrome.storage.session`. La clé API ne quitte jamais le service worker (tâche 1 d'abord).

**Tech Stack:** Chrome MV3, JS sans build (motif UMD `globalThis.JEV`), `node:test` + jsdom (`npm test`).

**Spec:** `docs/superpowers/specs/2026-10-03-auto-mode-design.md` (commit 7587d7e). Les exécutants lisent la spec ET ce plan.

## Global Constraints

- Seul `extension/src/auto/executor.js` appelle `.click()`, assigne une valeur de champ ou appelle `dispatchEvent`/`new *Event` ; exemption fermée : `extension/src/context.js` (clics sur l'iframe CACHÉ). Les autres fonctions de l'extension restent en lecture seule.
- La clé API n'est jamais lisible dans un fichier listé dans `content_scripts` (aucune occurrence du mot `apiKey`) ; `'apiKey' in settings` côté page → ARRÊT.
- Le score JEV n'est pas une probabilité : jamais « probabilité × cote ». Une sélection n'est retenue que si `confidence` est un nombre ≥ `minConfidence` ; `null` = refus.
- Mise = min(10 % du solde de départ, `suggestStake`), arrondie à l'inférieur au centime. Perte de session ≤ 50 % du solde de départ, réserve incluse. ≤ 5 paris Auto par session. 3 défaites d'affilée → ARRÊT.
- Plafonds durs : `minOdds` ≥ 1,20 (défaut 1,30) ; `maxOdds` ≤ 6,00 (défaut 4,00) ; `maxDriftPct` ≤ 5 (défaut 3) ; `minLeadSec` ≥ 60 (défaut 90) ; `minConfidence` ≥ 0,50 (défaut 0,60) ; `confirmTimeoutMs` ≤ 15000 (défaut 8000) ; onglet masqué toléré ≤ 10 s (défaut 5 s). Valeur hors plafond → ARRÊT au démarrage.
- Jamais de nouvel essai après un échec ; ARRÊT collant ; jamais de clic sur `[data-qa=bet-confirmation-keep-selections]` ni sur un `#betBtn` dont le libellé n'est pas « Parier ».
- Le solde se lit en direct (`bc-header-wallets .header_walletBalance span`), jamais depuis `ng-state`.
- Pas d'`eval`, pas de HTML non échappé, logs `[JEV]` via `log/warn/error` de `utils.js`, valeurs inconnues de l'API centralisées dans `config.js`. Commits terminés par `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` ; aucun tag, aucun push sans demande.

## Review Focus

- Montants à virgule et espace insécable (« 6,53 € », « 0,65 € ») : `parseMoney` doit donner 6.53 / 0.65, et `null` (jamais 0) si illisible → ARRÊT. (tâche 3)
- Temps additionnel « 45+2' », « MT », « Débute », « Fin Q1 » : minute illisible = trop court, jamais un clic. (tâche 4)
- Solde en pleine animation (`bc-header-animated-balance`) : lire deux fois à 300 ms d'écart, refuser si différent. (tâche 7)
- JEV renvoie une sélection absente de la liste blanche ou un `marketId` inconnu : ignorée, jamais jouée. (tâche 6)
- Deux onglets Betclic armés en même temps : l'état de session porte un `ownerTabId`, le second onglet se met en ARRÊT. (tâche 9)
